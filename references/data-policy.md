# LG 投资模型数据规范

## 原则

API 只能提高取数效率，不能单独保证准确。准确性来自一手来源、字段口径、时间状态、交叉验证、计算复核和失败拦截。

Skill 不保存易过期行情。涉及“现在、今天、最新、当前价、财报、宏观、期权链”时，必须在回答当次重新核验。

## 来源层级

| 数据 | 第一优先 | 补充核验 |
|---|---|---|
| 美股财报与公告 | SEC EDGAR、公司投资者关系页面 | 交易所正式公告 |
| A 股公告 | 巨潮资讯、上交所、深交所、北交所 | 公司正式披露 |
| 港股公告 | HKEXnews、公司正式披露 | 监管机构公告 |
| 宏观 | 央行、统计机构、政府部门、FRED | 其他同口径官方数据库 |
| 股票与 ETF 行情 | 券商或交易所授权行情 | 两个可靠行情源交叉核验 |
| 期权合约与行情 | 券商或交易所授权行情、OCC | 用户提供且字段完整的券商快照 |

搜索摘要、社交媒体和财经媒体只能用于发现线索。关键事实应回到原始披露；一手与二手冲突时采用一手口径并披露差异。

精确的股票或 ETF 当前价格、精确买点或操作指令只能使用交易所、券商或其他授权的市场数据。两个可靠、免费或公开行情源即使数值一致，也只表示交叉核验通过，不会升级为实时、授权或可成交数据；仍按实际状态标记为延迟数据、最近收盘或二手数据，置信度较低。

## API 与凭据

公开 Skill 不绑定单一供应商，也不内置 API Key 或账户凭据。优先使用运行环境已经授权的浏览、官方接口或行情连接；实时盘中和期权链需要用户自己的券商账户及相应行情权限。

接口鉴权失败、限流、超时或权限不足时，不自动改用未知缓存。可以改用已核验最近收盘或延迟数据，但必须更换准确性标签并说明这会如何限制结论。

## 准确性标签

- `一手已核验`：来自监管、交易所、政府、公司正式披露或授权行情。
- `交叉已核验`：两个可靠来源在代码、币种、单位、期间和时间上口径一致。
- `延迟数据，截至 YYYY-MM-DD HH:MM 时区`：可靠但不是实时数据。
- `二手数据，置信度较低`：暂时只有非一手材料，不能支撑高精度操作。
- `暂未核实`：数据缺失、冲突、接口失败或口径无法确认。

准确性标签可以组合使用。交叉已核验只描述同口径数据一致，不描述数据的时效性、授权状态或可成交性。交叉一致的延迟数据仍同时标记为 `交叉已核验` 和 `延迟数据，截至 YYYY-MM-DD HH:MM 时区`；没有授权行情时，不得据此输出精确当前价或可执行操作。

## 最小数据卡

每个影响结论的关键数字记录：

1. 公司名称、证券代码和交易所；
2. 数值、单位和币种；
3. 财报期或行情时间；
4. 时区以及盘前、盘中、收盘或盘后状态；
5. 价格口径标明末笔成交价、买价/卖价或收盘价，以及复权或未复权；财报口径标明 GAAP 或非 GAAP；
6. 来源名称和原始链接；
7. 获取时间和准确性标签。

同名证券、ADR、普通股、不同上市地和不同币种不得凭简称合并。财报不得混用单季、累计、滚动期间或不同股本口径。

最小数据卡任一必需字段缺失时，停止输出精确价格、买点或操作、仓位、盈亏和期权指令。某项口径与当前数据无关时必须明确标记为不适用，不得留空或默认推断。

## 价格与接货区间

先用正常化盈利、现金流或适合该业务的量尺形成悲观、基准、乐观价值范围，再结合最新已核验行情决定分批条件。

输出至少包含当前参考价及状态、三种情景的假设、分批区间、每档触发条件、停止增加条件和基本面失效线。没有时间戳、交易时段或可靠行情时不输出精确买点。

## 期权

精确期权结论必须核验标的、交易所、到期日、行权价、方向、乘数、买卖报价、报价时间、币种、成交量、持仓量和价差。

缺少授权合约链时不输出可下单合约、权利金或精确盈亏。理论价值不得描述为可成交价格；用户截图若缺少时间和字段，只能作为待核验线索。

## 计算与冲突

估值、增长率、收益率和期权盈亏都列出事实输入、假设输入、单位、币种、期间和公式。汇率换算同时记录汇率来源与截至时间。

数据冲突时依次检查期间、币种、单位、会计口径、股本、复权方式和交易时段。同口径仍冲突时采用更高层级来源并列出差异；无法解决则标记“暂未核实”。

## 强制停止精确结论

以下任一情况成立时，停止精确价格、仓位、盈亏或期权指令：

- 代码、交易所或币种有歧义；
- 缺少授权行情访问，无法取得交易所、券商或其他授权市场数据；
- 当前价格没有时间戳；
- 盘中、收盘和盘后状态无法区分；
- API 失败或行情权限不足；
- 官方披露与其他数据冲突且无法校准；
- 期权合约字段或实时链不完整；
- 财报期、单位、股本或复权方式无法对齐。

失败回答必须写出已经确认的事实、缺失字段、需要用户补充的数据和可继续执行的条件分析。
